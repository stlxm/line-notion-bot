# LINE Notion Bot

LINEを入口に、家計簿・予算・カード利用通知・固定費/サブスク・貸し借り・メモ・Notion・Gemini AIをまとめて扱う個人向けBotです。

## ドキュメント

- `SETUP.md`: 初期構築、環境変数、Notion DB、GAS、Render設定
- `MAINTENANCE.md`: 日常保守、障害切り分け、復旧
- `DEVELOPMENT.md`: 長期ロードマップ、進捗、次回再開位置
- `UI_DESIGN.md`: LINE UIとPostback設計ルール
- `PHASE1_TEST.md`: カード自動化テスト
- `PHASE2_TEST.md`: 月次・予算判断テスト
- `PHASE3_TEST.md`: Phase 3A/3B テスト
- `FLYER_TEST.md`: サミットチラシ・生活カレンダー実機テスト

機能変更時は README.md / SETUP.md / DEVELOPMENT.md を更新し、UI変更時は UI_DESIGN.md も更新します。

# Phase 3A — 自然文家計簿入力・支出テンプレート

状態: **実装済み・要実機確認**

普通の文章から支出を読み取れます。

```text
今日サミットで2380円使った
昨日コンビニで540円買った
9月10日にスタバで680円払った
```

金額・店名・日付を読み取り、ジャンルや支払方法が文中にない場合はLINEのボタンで確認します。最終確認の「この内容で登録」を押すまでNotionへ保存しません。

使い方確認:

```text
自然文入力
```

よく使う支出:

```text
支出テンプレート
```

直近90日の家計簿から、よく使う `店名 + ジャンル + 支払方法` を自動で候補化し、金額はその組み合わせの中央値を表示します。テンプレートも確認後に登録します。専用DBは不要です。

# ジャンル別予算

`予算 お菓子 3000` のようなジャンル予算に対応しています。

```text
予算 100000
予算 お菓子 3000
予算 2026-10 食費 35000
```

月別管理DBに `お菓子予算` のようなNumberプロパティがまだ存在しない場合は、Botがその列を自動追加してから保存します。これにより、新しいジャンルの予算設定でNotion更新が失敗しにくくなっています。

# Phase 3B — 直前登録の修正・取り消し

状態: **実装済み・要実機確認**

```text
直前登録
直前修正
直前取り消し
```

`直前登録` で家計簿DBの最新1件を表示し、次を修正できます。

```text
金額
店名
日付
ジャンル
支払方法
```

例:

```text
直前修正 金額 1500
直前修正 店名 サミット
直前修正 日付 2026-09-12
直前修正 ジャンル 食費
直前修正 支払方法 JCB
```

`直前取り消し` は対象を表示して確認後、Notionページをアーカイブします。いきなり消しません。

# 貸し借り管理

状態: **実装済み・要実機確認**

```text

借りた 田中 2000
```

貸し借りは家計簿とは別管理です。`精算` は相手+金額が未精算レコードに1件だけ一致するときだけ更新します。

# 「この機能ある？」案内

状態: **実装済み・要実機確認**

```text
機能確認 貸し借り
機能確認 自然文家計簿
機能確認 本日のレポート
貸し借りの記録ってできる？
```

判定順:

```text
1. 登録済み機能名・別名で確認
2. 見つからなければGeminiが既存機能一覧から推定
3. 既存機能で可能 → 使い方を回答
4. ロードマップ済み → 未実装と予定を回答
5. Geminiも「ない」と判断 → 入力された機能名を機能追加要望DBへ登録
```

Gemini障害時は誤って要望DBへ登録しません。

Render環境変数:

```text
NOTION_FEATURE_REQUEST_DATABASE_ID=76e4fe5d248e4fd1a48f45e9bdd59e8c
```

# ボタンを押したことがすぐ分かるUI

LINEの `message` action は押した瞬間に選択内容がトークへ表示されます。Postbackが必要なボタンには `displayText` を追加しています。

Phase 3Aのジャンル・支払方法・最終確認も `message` action を使うため、Botの処理完了前にタップしたことがトーク上で分かります。
